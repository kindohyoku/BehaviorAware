TL;DR Behavior-Aware Anthropometric Scene Generation is a framework that asks a vision–language model how people will act in a space, compiles those actions into body-parameterized geometric constraints, and solves them into a 3D layout that real users can walk, sit, reach, and manipulate within — not just look at.

Overview

1

Behavioral Affordance Analysis

A VLM reads each Objaverse asset's functional description and predicts the top-five human actions it affords — open, push, pull, touch, close. Behavior becomes a first-class input, not an after-the-fact constraint.

2

Semantic Grouping

An LLM clusters assets into functional zones (individual work area, storage area, …) and emits explicit intra-group and inter-group spatial relations, so the layout reflects how people actually use rooms.

3

Anthropometric Constraints

Every distance, orientation, and clearance term is parameterized by user body dimensions (shoulder width H4, arm reach H3, sitting height V1…) and solved with a Blender constraint solver per individual.

4

Validated by Motion Capture

Individual (60 min) and group (120 min) studies in an 8-camera mocap room record SMPL trajectories. Layouts produced by our framework show shorter task time, fewer detours, and larger usable manipulation volume.

Abstract

Well-designed indoor scenes should prioritize how people can act within a space rather than merely what objects to place. However, existing 3D scene generation methods emphasize visual and semantic plausibility, while insufficiently addressing whether people can comfortably walk, sit, or manipulate objects.

We present a Behavior-Aware Anthropometric Scene Generation framework that leverages vision–language models to analyze object–behavior relationships and translates spatial requirements into parametric layout constraints adapted to user-specific anthropometric data. Through individual and group user studies with motion-captured trajectories, we show that layouts generated with our framework yield shorter task-completion times, fewer detours, cleaner action sequences, and a substantially larger usable manipulation volume than path-only and baseline layouts.

Method

Our pipeline factors scene generation into two stages: a Semantic and Behavioral Representation built by a VLM/LLM (A–E), then a Constraint-based Layout Generation stage that compiles and solves anthropometric constraints (F–G).

Step 1

Input Assets & Functional Description

Each Objaverse asset is rendered from multiple views in Blender. The VLM returns a functional description — which faces must stay clear, which parts move, how the part is meant to be used.

Step 2

Human–Object Interaction Pattern

For every asset we prompt the VLM for the top-five actions it affords. These actions later determine the kinematic volume that must remain unobstructed around the object.

open push pull touch close
Step 3

Semantic Grouping & Constraint Compilation

An LLM clusters assets into functional groups and writes intra-group and inter-group spatial relations. These are emitted as Blender constraint solver calls parameterized by the user's anthropometry. 

solver = ConstraintSolver()
width_d = desk.width * 2          # Desk + Desk
depth_d = desk.depth + chair.depth # Desk + Chair

for i in range(N):
    # Orientation constraint — against wall, for space efficiency
    solver.against_wall(desks[i], walls[0])

    # Position constraint — accessibility gap + half widths
    if i < N-1:
        solver.distance_constraint(desks[i], desks[i+1],
            min=0.1 + (width_d / 2),
            max=0.3 + (width_d / 2) + Tolerance)

    # Chair facing the desk
    solver.point_towards(chairs[i], desks[i])
Step 4

Sequential Group Optimization

Groups are solved one after another so later groups inherit the geometry of earlier ones, producing a Behavior-Aware Anthropometric Scene tailored to the participant's body.

Key concept

Human–Object Manipulation Space

We define a per-action 3D bounding volume sized by the user's anthropometry that must stay collision-free for the action to be physically achievable. Reserving this volume — not just a 2D walkable path — is what separates Human-Operational layouts from prior Path-Only approaches.

Experiments

We compare three layout conditions across two scene categories under both individual and group tasks.

Baseline Existing scene-generation method, no behavior reasoning.
PO · Path-Only Reserves a navigable path between objects.
HO · Human-Operational (Ours) Reserves the full anthropometric manipulation volume for every action.

Experimental Setup

9 × 9 × 2.5 m motion-capture room; 5.5 × 5.5 m action zone; 8 cameras; per-participant video + 3D keypoint + SMPL JSON capture.

Study Protocol

Rating Interface

Each generated scene was rated on five axes — Position, Orientation, Semantic Plausibility, Physical Plausibility, and Functional Accessibility — via a top/side-view interface.

Results

Metrics at a glance

Task Completion Time sec, lower is better

How quickly participants finished the assigned task.

Trajectory Count #, lower is better

Number of distinct path branches per participant. Fewer means fewer detours and clearer wayfinding.

Sequence Action Labeling #, lower is better

Action-state transitions during the task. Lower indicates a cleaner, more direct action chain.

Volumetric Occupancy Ratio 0–1, higher is better

Fraction of the reserved manipulation volume actually filled by the participant's body. Higher means the space fits the action.
